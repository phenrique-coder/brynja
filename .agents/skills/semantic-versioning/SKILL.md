# Semantic Versioning & Changelog — Brynja

Every code change that alters application behavior, UI, security guardrails, or APIs must:
1. Bump `"version"` in `package.json` following **SemVer 2.0.0 (`MAJOR.MINOR.PATCH`)**.
2. Document the changes under the new version heading in **both** `CHANGELOG.md` (English) and `docs/pt-BR/CHANGELOG.md` (Português — Brasil) following **Keep a Changelog 1.1.0**.

## Version Bump & Changelog Category Rules

| Change Type | Conventional Commit | Bump | Changelog Section (EN / PT-BR) | Example |
| --- | --- | --- | --- | --- |
| Breaking API, session/certificate format, or IndexedDB schema change | `feat!:`, `fix!:`, or `BREAKING CHANGE:` | `major` | `Changed` / `Alterado` (marked **BREAKING**) | `1.1.0` → `2.0.0` |
| New backward-compatible feature (new Safe Probe, parser, UI page/component, exporter, or workflow) | `feat:` | `minor` | `Added` / `Adicionado` | `1.0.0` → `1.1.0` |
| Bug fix, UI alignment fix, false-positive fix, or resilience/perf improvement | `fix:`, `perf:` | `patch` | `Fixed` / `Corrigido` (or `Changed` / `Alterado`) | `1.1.0` → `1.1.1` |
| Security guardrail or dependency vulnerability patch | `security:`, `fix(security):` | `patch` | `Security` / `Segurança` | `1.1.0` → `1.1.1` |
| Pure docs, tests, comments, or internal chores with zero runtime impact | `docs:`, `test:`, `chore:` | *(none)* | *(none required unless requested)* | unchanged |

> **Mixed commits:** If a single delivery includes both a `feat` and a `fix`, apply the highest applicable bump (`major` > `minor` > `patch`) and list every change under its respective changelog section (`Added` + `Fixed`, etc.).

## Single Source of Truth

- `package.json` (`"version"`) is the canonical version consumed automatically by `src/features/scans/components/Footer.tsx` and `src/features/scans/registries/finding-registries.ts` (CycloneDX SBOM).
- `docs/pt-BR/CHANGELOG.md` is parsed directly at build/render time by `src/app/changelog/page.tsx` (`/changelog`), so updating the markdown files immediately updates both GitHub and the in-app `/changelog` screen.

## Mandatory Procedure

1. Determine the highest bump level (`major`, `minor`, or `patch`) from the table above.
2. Run the helper script from the repository root with `--scaffold` to bump `package.json` and insert the new dated `## [X.Y.Z] - YYYY-MM-DD` section into both changelogs:
   - Script: [bump-version.mjs](./scripts/bump-version.mjs)
   ```bash
   node .agents/skills/semantic-versioning/scripts/bump-version.mjs patch --scaffold
   # or: minor | major (add --dry-run to preview without modifying files)
   ```
3. Fill in concise, user-facing bullet points under the appropriate sections in:
   - `CHANGELOG.md` (English: `Added`, `Changed`, `Fixed`, `Security`, `Removed`)
   - `docs/pt-BR/CHANGELOG.md` (Português: `Adicionado`, `Alterado`, `Corrigido`, `Segurança`, `Removido`)
   *(Remove any unused placeholder headings generated by `--scaffold`.)*
4. Validate before committing:
   ```bash
   node .agents/skills/semantic-versioning/scripts/bump-version.mjs --check
   pnpm typecheck && pnpm test
   ```
5. Commit `package.json`, `CHANGELOG.md`, and `docs/pt-BR/CHANGELOG.md` together with the feature or patch.
